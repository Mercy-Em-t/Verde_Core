Contractor Assignment Rules

Never assign abstract tasks like "Build Receiving Screen" to subcontractors. Subcontractors are paid per issue. Tickets must have explicit Acceptance Criteria (DoD) directly referencing the API Endpoint Specs and Data Dictionary.

Backend BE-401: Implement POST /api/v1/warehouse/receive Endpoint
Estimate: 4 Story Points

Description

Build the express.js controller and service logic for the dock receiving scanner payload. The endpoint must parse the incoming GS1-128 barcode data and increment the stock ledger in a single atomic transaction.

Definition of Done (Acceptance Criteria)

  • Payload explicitly matches the Master API Endpoint Spec (POST /receive).
  • Implement Rule CNF-01: Reject request with `422 Unprocessable` if `qty_received` exceeds `qty_authorized * 1.05`.
  • Database commit must be wrapped in a PostgreSQL `BEGIN...COMMIT` block to ensure `TBL_RCV_LINES` and `TBL_ITEM` are updated atomically.
  • Unit tests written covering the +5% tolerance limit edge case.

Frontend FE-210: Zebra TC21 Scanner UI - Receiving Tally View
Estimate: 3 Story Points

Description

Implement the React Native UI for the receiving clerk. This screen is rendered on a Zebra TC21 Android device. It handles the physical hardware scan broadcast event.

Definition of Done (Acceptance Criteria)

  • Adhere to NFR-Ergonomics: All tap targets must be a minimum of 48x48 dp for gloved warehouse use.
  • Intercept the hardware scanner intent (DataWedge intent broadcast) to auto-fill the SKU input field without requiring keyboard focus.
  • If the API returns `422 Unprocessable` (Tolerance Exceeded), render a full-screen red modal requiring a Supervisor PIN override.
  • Offline state: Display 'Network Disconnected' banner and disable the 'Commit Batch' button.
