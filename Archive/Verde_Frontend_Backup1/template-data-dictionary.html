================================================================================ DATA DICTIONARY & LEVEL 2 PROCESS SPECIFICATIONS ================================================================================ PROJECT: OmniLogix Multi-Branch Platform

In full systems engineering, the Data Dictionary defines every data flow, data element, and persistent data store to prevent ambiguities before entering physical database design (Phase 3).

1. Data Store Specifications

Data Store: D1: PURCHASE_ORDERS

Description: Master relational store containing vendor commitments, line manifests, and delivery status.

Physical Mapping: Maps directly to TBL_PO_HEADER and composite lines in TBL_RCV_LINES.

Inbound Flows: Validated PO Records (from Process 1.0).

Outbound Flows: Expected Line Item Manifests (to Process 2.0 & 2.1).

Data Store: D2: INVENTORY_BALANCES

Description: Real-time stock ledger storing atomic on-hand counts per SKU, warehouse depot, and physical bin location.

Physical Mapping: Maps to TBL_ITEM, TBL_WAREHOUSE, and physical ledger balance records.

Inbound Flows: Validated Unit Stock Increments (from Process 3.0).

Outbound Flows: Current Stock Velocity and Reorder Thresholds (to Process 5.0).

Data Store: D3: AUDIT_TRAIL_LOGS

Description: Append-only cryptographic ledger tracking every operational mutation, clerk identifier, and terminal timestamp.

Physical Mapping: Write-only relational audit partition.

Inbound Flows: Immutable Transaction Hash & Metadata (from Process 4.0).

Outbound Flows: Audit queries for compliance under the Kenyan Data Protection Act (KDPA).

2. Composite Data Flow Dictionary Entries

Data Flow: Validated Expected SKU Manifest (Process 1.0 → Process 2.0)

Manifest = PO_Number + SupplierID + {SKUID + SKUName + QtyOrdered + MaxToleranceQty} + OrderStatus

Data Flow: Buffered Physical Scans (Receiving Clerk → Process 2.0)

ScanPayload = TerminalUUID + ClerkID + ScanTimestamp + {BarcodeRaw + ScannedSKU + QtyTally} + NetworkState

Data Flow: Cryptographic GRN & Discrepancy Escalation (Process 4.0 → Finance / External)

GRNPayload = GRN_Number + ReceiptID + PO_Number + ReceiptDate + {SKUID + QtyAccepted + VarianceCode} + HashSig
