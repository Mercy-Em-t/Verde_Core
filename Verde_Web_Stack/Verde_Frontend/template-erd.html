Normalization Protocol

Data Integrity Mandate

All logical schemas modeled by the Systems Analyst must strictly adhere to the Third Normal Form (3NF) before Phase 2 can be closed. Update, Insertion, and Deletion anomalies will not be tolerated in physical execution.

1NF (First Normal Form)

Eliminate repeating groups. Every field is made atomic, and a composite primary key is defined on associative entities (e.g., receiving line manifests `[ReceiptID, SKUID]`).

2NF (Second Normal Form)

Remove partial functional dependencies. Attributes depending only on a portion of the composite key are separated (e.g., Supplier/Warehouse isolated from SKU specifics).

3NF (Third Normal Form)

Remove transitive dependencies. Attributes dependent on other non-key fields (e.g., `ClerkName` depending on `ClerkID`) are isolated into independent master lookup tables.
